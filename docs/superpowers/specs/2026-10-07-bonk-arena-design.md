# 통통 대전 설계 문서

작성일: 2026-10-07

## 1. 목적

브라우저에서 실행하는 실시간 물리 대전 게임입니다. Bonk.io처럼 여러 사람이 한 맵에서 공을 조종하여 서로 밀어내고, 마지막까지 맵 위에 남은 사람이 라운드를 이깁니다. 방을 만들어 친구와 최대 6명까지 같이 할 수 있고, 혼자일 때는 AI 상대와 연습할 수 있습니다.

재미를 위한 개인 프로젝트이며, 완성한 뒤에는 claude.ai 아티팩트와 공개 사이트 두 곳에 올려서 다른 사람과 같이 합니다. 게임 이름인 "통통 대전"은 임시로 정한 것이므로 바꿀 수 있습니다.

### 성공 기준

- `npm run dev`로 실행한 뒤 처음 화면에서 연습하기를 골라, AI 상대와 한 경기를 최종 결과 화면까지 진행할 수 있습니다.
- 공이 구르고 부딪치고 튕기는 움직임이 Bonk.io와 비슷하게 느껴지며, 조작이 지연 없이 바로 반영됩니다.
- 클래식, 갈고리, 화살 세 모드를 모두 고를 수 있고, 모드마다 X 키가 정해진 특수 동작을 수행합니다.
- 브라우저 탭 두 개로 방 만들기, 초대 링크로 들어가기, 준비, 시작, 라운드 승패 판정, 최종 결과, 다시 하기까지 진행할 수 있습니다.
- 같이 하는 동안 상대의 공이 내 화면에서 끊기지 않고 움직이며, 상대 공과 내 공이 실제로 서로 밀어냅니다.
- 방장이 대전 도중에 나가도 남은 사람들이 같은 점수표로 경기를 계속할 수 있습니다.
- 키보드와 터치 화면 버튼 가운데 어느 것으로도 조작할 수 있습니다.
- `npm test`와 `npm run build`가 오류 없이 통과합니다.

### 범위에서 제외하는 것

- 맵 편집기와 맵 공유
- 꾸미기(스킨), 팀전, 전적 저장, 순위표
- 움직이는 발판과 부서지는 발판(모든 발판은 고정되어 있습니다)
- 배경 음악
- 모든 화면에서 충돌 결과가 완전히 일치하도록 보장하는 동기화(5장 '한계' 참고)
- 두 곳에 실제로 올리는 작업(로컬에서 완성본을 확인한 뒤 따로 진행합니다)

## 2. 기술 구성

- Vite + TypeScript + Vitest를 사용하며, 형제 프로젝트인 `suika-game`과 같은 구성을 따릅니다.
- UI 프레임워크는 사용하지 않습니다. 게임 화면은 Canvas 2D에 직접 그리고, 처음 화면, 대기실, 결과 화면처럼 버튼과 입력 칸이 있는 화면은 HTML 요소를 캔버스 위에 겹쳐서 만듭니다.
- 실행 의존성은 `planck`(물리)와 `peerjs`(공개 사이트의 같이 하기) 두 개입니다. `peerjs`는 공개 사이트용 빌드에서만 불러오므로 아티팩트용 빌드에는 포함되지 않습니다.
- 저장소 위치는 `game-projects/bonk-arena/`이며 독립된 git 저장소로 관리합니다.

### 물리 엔진을 planck로 정한 이유

planck는 Bonk.io가 사용하는 Box2D를 JavaScript로 옮긴 엔진이므로, 공이 튕기고 밀리는 느낌을 원작과 비슷하게 맞추기 쉽습니다. 갈고리에 필요한 줄 연결(RopeJoint)과, 빠르게 날아가는 화살이 얇은 발판을 뚫고 지나가지 않게 하는 연속 충돌 검사도 기본으로 제공합니다.

### 폴더 구조

| 경로 | 맡는 일 |
|---|---|
| `src/physics/world.ts` | 맵과 공을 물리 세계로 만들고, 고정 간격으로 계산합니다. 입력 적용, 무거워지기, 줄, 화살, 경계 밖 판정을 처리합니다. |
| `src/game/maps.ts` | 맵 16개의 자료와, 움직이는 발판의 시간별 위치 계산입니다. |
| `src/game/modes.ts` | 모드 세 가지의 이름과 수치입니다. |
| `src/game/round.ts` | 경기 진행 단계와 점수를 관리합니다. |
| `src/game/bot.ts` | AI의 입력을 정합니다. |
| `src/net/*` | `suika-game`의 통신 코드를 가져와서 씁니다. claude.ai의 room 기능과 P2P 연결이 같은 인터페이스를 따릅니다. |
| `src/multiplayer.ts` | 내 상태를 올리고, 받은 상태로 상대 공을 맞추고, 방장을 정합니다. |
| `src/session.ts` | 물리, 진행, 통신, 입력을 묶어서 한 경기를 실행합니다. |
| `src/render/*` | 맵, 공, 줄, 화살, 점수표, 효과를 그립니다. |
| `src/ui/menus.ts` | 처음 화면, 대기실, 결과 화면을 만듭니다. |
| `src/input.ts` | 키보드와 터치 버튼의 입력을 읽습니다. |
| `src/audio.ts` | 효과음을 재생합니다. |
| `src/storage.ts` | 이름과 색을 저장합니다. |

`physics`와 `game`은 화면과 통신에 의존하지 않으므로, 브라우저 없이 자동 테스트로 확인할 수 있습니다.

## 3. 규칙

### 공통 규칙

- 한 경기는 여러 라운드로 이루어집니다. 라운드에서 마지막까지 남은 한 명이 1점을 얻습니다.
- 공의 중심이 맵의 경계 밖으로 나가면 그 라운드에서 탈락합니다. 경계는 화면의 왼쪽, 오른쪽, 아래쪽으로 각각 2m 바깥에 있습니다. 위쪽으로는 탈락하지 않습니다.
- 남은 사람이 동시에 모두 탈락하거나 라운드가 90초를 넘기면 무승부이며, 아무도 점수를 얻지 못합니다.
- 방장이 정한 목표 점수(3점, 5점, 7점 가운데 하나, 기본값은 5점)에 먼저 도달한 사람이 우승합니다.
- 라운드가 시작되기 전에 3초 동안 카운트다운을 하며, 그동안에는 공이 움직이지 않습니다.
- 라운드가 끝나면 2초 동안 결과를 보여 준 뒤 다음 라운드로 넘어갑니다.
- 방장은 대기실에서 맵을 "무작위" 또는 특정 맵으로 정합니다. 무작위이면 라운드마다 직전 라운드와 다른 맵이 나옵니다.

### 조작

| 입력 | 동작 |
|---|---|
| ← → | 공에 왼쪽 또는 오른쪽으로 힘을 줍니다. |
| ↑ | 공이 발판이나 다른 공에 닿아 있을 때 뜁니다. |
| ↓ | 공에 아래쪽으로 힘을 줍니다. |
| X | 모드에 따른 특수 동작을 합니다. |

WASD 키도 방향키와 같은 동작을 합니다. 터치 기기에서는 화면 왼쪽 아래에 방향 버튼 네 개, 오른쪽 아래에 특수 동작 버튼 한 개를 표시합니다.

### 모드

**클래식: 무거워지기**

- X를 누르고 있는 동안 공의 질량이 3배가 됩니다.
- 공에 주는 힘과 뛰는 힘은 그대로이므로, 무거운 동안에는 가속과 뛰어오르는 속도가 3분의 1로 줄어듭니다.

**갈고리: 줄 걸기**

- X를 누르는 순간, 공의 중심보다 위에 있는 발판 표면 가운데 공에서 가장 가까운 지점에 줄이 걸립니다. 8m 안에 그런 지점이 없으면 아무 일도 일어나지 않습니다.
- 줄의 길이는 걸리는 순간의 거리로 고정되며, 공은 그 길이보다 멀어질 수 없습니다.
- X를 떼면 줄이 풀립니다.

**화살: 쏘기**

- X를 누르고 있는 동안 힘이 모이고, 떼는 순간 화살이 날아갑니다. 모으는 시간은 0.2초에서 1초까지 반영되며, 화살의 속력은 그에 비례하여 초속 12m에서 30m 사이로 정해집니다.
- 모으는 동안에는 방향키가 공을 움직이지 않고 겨누는 방향(8방향)을 정합니다. 방향키를 누르지 않으면 마지막으로 움직인 좌우 방향으로 쏩니다.
- 날아가는 화살에 닿은 사람은 탈락합니다. 자기가 쏜 화살에는 맞지 않습니다.
- 화살은 중력의 영향을 받으며, 발판에 닿으면 그 자리에 꽂힙니다. 꽂힌 화살은 아무도 탈락시키지 않고 3초 뒤에 사라집니다. 쏜 지 5초가 지난 화살도 사라집니다.
- 한 번 쏜 뒤에는 1초 동안 다시 모을 수 없습니다.

### 물리 수치

화면은 가로 32m, 세로 18m인 세계를 보여 주며, 창의 크기에 맞추어 16:9 비율을 유지한 채 확대하거나 축소합니다. 아래 수치는 시작값이며, 구현하면서 손맛에 맞게 조정할 수 있습니다. 모든 수치는 `src/game/modes.ts`와 `src/physics/world.ts`의 상수로 모아 둡니다.

| 항목 | 값 |
|---|---|
| 계산 간격 | 1/60초 고정 |
| 중력 | 아래쪽으로 20 m/s² |
| 공의 반지름 | 0.5m |
| 공의 탄성 | 0.5 |
| 공의 마찰 | 0.3 |
| 좌우와 아래로 주는 힘 | 보통 질량의 공을 18 m/s²로 가속하는 힘 |
| 뛰는 힘 | 보통 질량의 공을 위쪽으로 초속 9m로 만드는 충격량 |
| 공기 저항(선형 감쇠) | 0.3 |

### 맵

발판은 사각형, 원, 다각형으로 이루어집니다. 맵마다 시작 위치가 6개 있고, 참가 순서와 라운드 번호로 시작 위치를 배정하므로 라운드마다 자리가 바뀝니다. 시작 위치는 움직이는 발판과 튕기는 발판 위에 두지 않습니다.

발판 장치는 두 가지입니다.

- **튕기는 발판**: 반발 계수가 1.25입니다. 튕길 때마다 빨라져서 끝없이 솟지 않도록, 튕겨 나가는 속력은 12m/s를 넘지 않습니다. 화면에는 초록색으로 그립니다.
- **움직이는 발판**: 상자 하나가 제자리에서 정해진 거리만큼 떨어진 곳까지 갔다가 정해진 주기마다 돌아옵니다. 위치는 play 단계가 시작된 뒤 지난 시간만으로 정해지며, 카운트다운 동안에는 제자리에 멈춰 있습니다. 방장은 자신이 진행하는 경과 시간을 그대로 쓰고, 나머지 참가자는 방장이 올린 경과 시간에 통신 지연 어림값(0.1초)을 더한 값 쪽으로 자기 시계를 맞춥니다. 발판을 딛고 있는 공은 발판과 함께 움직입니다. 발판에 꽂힌 화살과 발판에 건 줄의 고정점도 발판을 따라 움직입니다. 움직이는 발판은 다른 발판과 1.2m 이상 떨어져서 다니므로 그 사이에 공이 끼지 않습니다.

| 이름 | 구성 |
|---|---|
| 평지 | 넓은 발판 하나가 가운데에 있습니다. |
| 두 섬 | 좌우에 발판이 하나씩 있고, 그 사이는 비어 있습니다. |
| 계단 | 높이가 다른 발판 세 개가 계단처럼 놓여 있습니다. |
| 그릇 | 양쪽 끝이 위로 올라간 비스듬한 발판들이 그릇 모양을 이룹니다. |
| 기둥 | 폭이 좁은 발판 여러 개가 간격을 두고 서 있습니다. |
| 언덕 | 큰 원 하나가 발판이어서, 가만히 있으면 양쪽으로 굴러떨어집니다. |
| 다리 | 양쪽 둑 사이에 가운데가 솟은 얇은 다리가 놓여 있습니다. |
| 선반 | 얇은 발판 네 개가 좌우로 엇갈려 층층이 놓여 있습니다. 위쪽 두 단에서는 내려올 수만 있습니다. |
| 구멍 | 바닥 가운데가 뚫려 있고, 구멍 한가운데 아래쪽에 튕기는 발판이 있습니다. |
| 골짜기 | 긴 비탈 두 개가 가운데에서 만나 V자를 이룹니다. |
| 징검다리 | 작은 발판 다섯 개가 높이를 번갈아 가며 떠 있습니다. |
| 쌍봉 | 큰 원 두 개가 겹쳐 봉우리 둘과 그 사이의 얕은 골을 이룹니다. |
| 방방 | 평평한 바닥의 두 군데가 튕기는 발판입니다. |
| 나룻배 | 양쪽 둑 사이를 발판 하나가 가로로 오갑니다. 건너편으로 가려면 이 발판을 거쳐야 합니다. |
| 승강기 | 낮은 층과 높은 층 사이를 발판 하나가 세로로 오르내립니다. |
| 시소 | 양쪽 둑 사이에서 발판 두 개가 서로 반대로 오르내립니다. |

### AI 상대

- 가장 가까운 생존자 쪽으로 움직입니다.
- 자기 아래에 발판이 없거나 발판의 끝에 가까워지면, 가장 가까운 발판의 가운데 쪽으로 돌아옵니다.
- 클래식 모드에서는 상대와 부딪치기 직전에 무거워집니다.
- 갈고리 모드에서는 아래에 발판이 없는 채로 떨어지고 있을 때 줄을 겁니다.
- 화살 모드에서는 상대가 12m 안에 있고 다시 쏠 수 있을 때, 상대 쪽으로 0.5초 동안 모은 뒤 쏩니다.
- 반응을 사람과 비슷하게 만들기 위해 입력을 0.15초마다 한 번만 바꿉니다.

## 4. 화면과 진행

### 화면 순서

1. **처음 화면**: 이름 입력, 색 고르기, "연습하기", "방 만들기", "방 들어가기"가 있습니다. 연결할 수 없는 환경에서는 연습하기만 누를 수 있습니다.
2. **대기실**: 참가자 목록, 준비 여부, 초대 링크 복사 버튼이 있습니다. 방장은 모드, 목표 점수, 맵, AI 수를 정하고, 모든 사람이 준비하면 시작할 수 있습니다. 연습하기에서는 같은 대기실을 혼자서 쓰며 AI를 1명에서 5명까지 넣습니다.
3. **대전 화면**: 맵과 공, 화면 위쪽의 점수표, 카운트다운, 라운드 결과 문구가 나옵니다.
4. **최종 결과**: 우승자와 점수표가 나오고, "대기실로 돌아가기"가 있습니다.

### 진행 단계

`round.ts`는 경기를 다음 단계로 관리합니다.

```
대기실 → 카운트다운(3초) → 대전(최대 90초) → 라운드 결과(2초) → 카운트다운 → …
                                                         └→ 최종 결과 → 대기실
```

- 대전 단계에서 생존자가 한 명 이하가 되면 라운드 결과 단계로 넘어갑니다.
- 라운드 결과 단계에서 누군가의 점수가 목표 점수에 도달했으면 최종 결과 단계로 넘어갑니다.

### 겉모습

- 배경과 발판은 단색이며, 원작처럼 단순한 도형만 사용합니다.
- 플레이어는 색이 다른 원입니다. 색은 파랑, 주황, 초록, 보라, 노랑, 청록 6가지이며, 한 방에서 같은 색을 두 사람이 쓸 수 없습니다. 다른 사람이 쓰고 있는 색은 대기실에서 고를 수 없게 표시합니다.
- 공에는 굴러가는 방향을 알 수 있는 선을 하나 긋고, 공 위에 이름을 표시합니다.
- 무거워진 공은 테두리를 굵게 그립니다. 줄은 공과 고정점을 잇는 선으로, 화살은 짧은 선으로 그립니다. 화살을 모으는 동안에는 겨누는 방향과 모인 힘을 공 옆에 표시합니다.
- 점수표는 화면 위쪽에 색 원과 숫자로 표시하고, 탈락한 사람의 원은 흐리게 표시합니다.
- 탈락할 때에는 경계 쪽에 짧은 효과를 보여 줍니다.

### 소리

효과음은 Kenney의 무료 효과음 묶음(impact-sounds, interface-sounds, CC0)을 사용합니다. 충돌(세기에 따라 음량 조절), 탈락, 화살 발사, 줄 걸기, 카운트다운, 라운드 승리, 버튼에 넣습니다. 파일은 mp3로 변환하여 빌드 결과물에 포함합니다. 출처는 README에 기록합니다.

### 저장

이름과 색을 localStorage의 `bonk-arena.profile.v1` 키에 저장합니다. 다른 키는 읽거나 지우지 않습니다.

## 5. 같이 하기

### 방식: 각자 자기 공을 계산합니다

모든 브라우저가 전체 물리 세계를 계산하되, 자기 공의 결과만 자기가 확정하여 다른 사람에게 알립니다. 조작이 즉시 반영되고, 방장이 나가도 경기가 끊기지 않습니다. 방장이 모든 것을 계산하는 방식은 참가자의 조작이 0.15초 이상 늦게 반영되어서 선택하지 않았고, 입력만 주고받는 결정론적 방식은 통신 계층을 새로 만들어야 해서 선택하지 않았습니다.

### 각자 올리는 상태

통신 계층은 사람마다 상태 하나를 올리고 모두가 그것을 받아 보는 방식입니다. `suika-game`과 같은 간격(60ms)으로 올립니다.

| 항목 | 내용 |
|---|---|
| `name`, `color`, `ready`, `joinedAt` | 이름, 색, 준비 여부, 방에 들어온 시각 |
| `round` | 이 상태가 속한 라운드 번호 |
| `ball` | 내 공의 위치, 속도, 회전 속도 |
| `input` | 지금 누르고 있는 입력(방향 네 개와 특수 동작) |
| `alive` | 이번 라운드에서 생존해 있는지 여부 |
| `rope` | 걸려 있는 줄의 고정점. 없으면 비워 둡니다. |
| `aim` | 화살을 모으고 있을 때의 방향과 모은 시간 |
| `arrows` | 내가 쏜 화살 가운데 아직 사라지지 않은 것들. 화살마다 번호, 발사 위치, 발사 속도, 쏜 뒤 지난 시간을 담습니다. |
| `host` | 방장만 올립니다. 모드, 목표 점수, 맵 설정, 현재 맵, 라운드 번호, 진행 단계, 그 단계가 시작된 뒤 지난 시간, 점수표, AI들의 상태(위 `ball`부터 `arrows`까지와 같은 항목)를 담습니다. |

### 상대 공을 맞추는 방법

- 상대 공도 내 물리 세계에 실제 물체로 두고, 마지막으로 받은 입력을 계속 적용합니다. 그래서 새 상태가 도착하기 전에도 상대 공이 자연스럽게 움직이고, 내 공을 실제로 밀어냅니다.
- 새 상태를 받으면 받은 위치와 내 화면의 위치를 비교합니다.
  - 차이가 1m(공의 지름) 미만이면, 상대 공의 속도를 "받은 속도 + 차이 × 6"으로 고쳐서 부드럽게 따라가게 합니다.
  - 차이가 1m 이상이면 받은 위치와 속도로 바로 옮깁니다.
- 내 공은 다른 사람이 보낸 상태로 고치지 않습니다. 내 화면에서 상대 공에 밀린 결과가 그대로 내 공의 결과가 됩니다.
- 줄은 받은 고정점으로 상대 공에 똑같이 걸어 줍니다.
- 화살은 받은 발사 정보로 내 세계에 똑같이 만들고, 쏜 뒤 지난 시간만큼 미리 계산하여 위치를 맞춥니다. 화살 번호로 이미 만든 화살인지 구분합니다.

### 판정

| 판정 | 정하는 사람 |
|---|---|
| 사람의 탈락(경계 밖, 화살 명중) | 탈락한 본인 |
| AI의 움직임과 탈락 | 방장 |
| 라운드의 승자, 점수, 다음 단계로 넘어가는 시점, 다음 맵 | 방장 |

방장은 방에 들어온 시각이 가장 이른 사람이며, 시각이 같으면 식별자의 사전 순서가 앞선 사람입니다. 참가자는 방장이 올린 진행 단계와 라운드 번호를 따라가고, 방장이 알려 준 "그 단계가 시작된 뒤 지난 시간"으로 카운트다운을 맞춥니다.

### 예외 상황

- **방장이 나간 경우**: 남은 사람 가운데 위 기준으로 다음 순서인 사람이 방장이 됩니다. 새 방장은 마지막으로 받은 `host` 내용(점수표, 라운드 번호, 진행 단계, AI 상태)에서 이어서 진행합니다.
- **대전 중에 누군가 나간 경우**: 그 사람을 탈락으로 처리합니다.
- **대전 중에 누군가 들어온 경우**: 그 사람은 구경하다가 다음 라운드부터 참가합니다. 점수는 0점에서 시작합니다.
- **정원(6명)을 넘는 경우**: 사람과 AI를 합쳐 6명까지입니다. 방이 가득 차 있으면 들어갈 수 없다고 안내합니다. 사람이 들어와서 6명을 넘게 되면 방장이 AI를 줄입니다.
- **연결할 수 없는 환경**: 연습하기만 할 수 있습니다.
- **탭이 가려진 경우**: 브라우저가 가려진 탭의 계산을 늦추므로, 0.5초 넘게 계산하지 못했다가 돌아오면 밀린 시간을 한꺼번에 계산하지 않고 현재 상태에서 이어 갑니다.

### 한계

- 충돌하는 순간의 결과가 화면마다 조금 다를 수 있습니다. 내 화면에서는 상대를 세게 밀었는데 상대 화면에서는 덜 밀린 것으로 계산되는 경우가 가끔 생깁니다.
- 화살은 맞은 사람의 화면을 기준으로 판정하므로, 쏜 사람의 화면에서는 맞은 것처럼 보였는데 탈락하지 않는 경우가 생길 수 있습니다.
- 통신 지연이 클수록 이 차이가 커집니다.

## 6. 확인 방법

### 자동 테스트

| 대상 | 확인하는 내용 |
|---|---|
| `physics/world` | 입력에 따라 공이 가속하는지, 닿아 있을 때에만 뛰는지, 무거워지면 질량이 3배가 되고 가속이 줄어드는지, 경계 밖으로 나가면 탈락으로 표시되는지 |
| `physics/world` (줄) | 위쪽의 가장 가까운 지점에 걸리는지, 8m 밖이면 걸리지 않는지, 줄의 길이보다 멀어지지 않는지, 떼면 풀리는지 |
| `physics/world` (화살) | 모은 시간에 따라 속력이 정해지는지, 날아가는 화살에 닿으면 탈락하는지, 자기 화살과 꽂힌 화살에는 탈락하지 않는지, 정해진 시간 뒤에 사라지는지, 다시 쏘기까지의 대기 시간이 지켜지는지 |
| `game/round` | 단계가 순서대로 넘어가는지, 생존자가 한 명일 때 점수가 오르는지, 무승부에서는 점수가 오르지 않는지, 목표 점수에 도달하면 최종 결과로 넘어가는지 |
| `game/maps` | 맵마다 시작 위치가 6개이고 모두 발판 위에 있는지, 시작 위치 배정이 라운드마다 바뀌는지 |
| `game/bot` | 발판 끝에서 안쪽으로 돌아오는지, 상대 쪽으로 움직이는지 |
| `multiplayer` | 상태를 올리고 읽는 형식이 서로 맞는지, 차이가 작을 때와 클 때의 맞추기 계산이 맞는지, 방장을 정하는 순서와 승계가 맞는지, 이미 만든 화살을 다시 만들지 않는지 |

### 브라우저 확인

- `npm run dev`로 연습하기를 열어 세 모드를 각각 한 경기씩 진행합니다.
- `npx vite --mode web`으로 탭 두 개를 열어 방 만들기부터 최종 결과까지 진행하고, 방장 탭을 닫았을 때 남은 탭이 경기를 계속하는지 확인합니다.
- 서로 다른 집이나 기기 사이의 대전은 로컬에서 확인할 수 없으므로, 배포한 뒤에 사용자가 직접 확인합니다.

## 7. 배포

이 문서의 구현 범위에는 배포가 포함되지 않습니다. 구현과 확인이 끝나면 다음 방법으로 올리되, 공개 저장소를 만드는 일과 게시하는 일은 사용자에게 다시 확인한 뒤에 진행합니다.

- claude.ai 아티팩트: `npm run build` 결과를 `game-projects/tools/build-artifact.mjs`로 HTML 한 장으로 묶어서 room 기능과 함께 게시합니다.
- 공개 사이트: `npm run build:web` 결과를 GitHub Actions로 GitHub Pages에 올립니다. 같이 하기는 P2P로 동작합니다.
